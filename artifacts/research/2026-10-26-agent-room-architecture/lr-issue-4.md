## Goal

Make QC failures loud, and make the QC stage's write\-back into `Room.py` trustworthy. Today a
crashed linter and a clean room produce the same result.

## Scope
- Remove or replace the `\|\| true` on every QC step in `run.sh` \(`:245`, `:246`, `:300`\) so a crash
is reported rather than swallowed. 
- Skip `qc\_collision \-\-apply` when the pre\-QC rebuild fails, instead of applying mesh\-derived
nudges computed from a stale `Room.glb`. 
- Stop deleting the linter's error in `collect\_qc` — `out.pop\("error", None\)` currently hides a
failed `qc\_room.qc\(\)` whenever a collision map is folded in. 
- Scope the bare `except Exception: pass` around the mesh fold, and surface a warning in the panel. 
- Tie the collision map to the current run instead of picking it by filename sort. 
- Add tests for `qc\_collision`'s FCL path and for the `Room.py` write\-back — neither is covered. 
- Validate on a real example scan: confirm reported violations match the room, and that applied
nudges improve it. 
- Document the default QC surface and reconcile it with the README's stage\-2 table — the model pass
is opt\-in \(`QC\_MODEL\_PASS=1`\) and off by default. 

## Acceptance criteria
- A QC step that crashes produces a visible failure, not a silent pass. 
- The viewer's QC panel and `qc.txt` agree on which checks actually ran. 
- No nudges are applied from a stale build. 
- The `Room.py` write\-back is covered by tests: still valid Python after the edit, `object.py`
untouched, over\-cap moves reverted. 
- Reported violations on an example scan match what the room actually shows. 
- Docs state which QC runs by default and which is opt\-in.
