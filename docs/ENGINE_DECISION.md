# 一期引擎选择：先验证网页高斯，不引入 UE5

2026-10-15，按用户询问的古村落实景还原案例做路线比较。

当前尚未定位用户描述的具体云南古村落视频，不能断言对方用了哪一种扫描和渲染方案。UE5 实景还原中存在“摄影测量网格 + Nanite”路线，也存在高斯插件路线，不应混为一谈。

## 本项目判断

- 视觉保真主要受输入拍摄、位姿、覆盖、重建、模型压缩与渲染设置影响。换引擎不会自动补齐漏拍的物体底部或柜内表面。
- 几何与尺度精度需用深度、实物测量、相机投影和碰撞代理分别验证。照片般的画面不等于已验证的一比一尺寸。
- Spark 能将独立高斯放进 Three.js 场景层级，与普通几何一起渲染和变换，符合浏览器访问、独立物品和简单开合目标。
- UE5 的完整游戏工具链适合以后复杂角色、物理、动画和大型场景制作。但仍需要拆分资产、补齐内部、定义关节，不能代替当前最困难的采集与对象化环节。
- 当前演示不是真实房间的精度验证。先取得一份实际样本，验证无重复物体、可正确拿起归位、背景补齐、尺度和网页性能，再决定是否需要第二个运行端。

保留独立资产与 scene.json，不把记忆内容、物品编号、关节参数绑定在某个引擎的专用工程里。未来如果接 UE5，另做资产与坐标适配器。
