# MemoryRoom 当前功能核对与手机扫描教程

日期：2026-10-26。依据：本次阅读当前 iOS、Mac 交接、场景、查看器、记忆、空间库和独立物品源码，以及本地文件和设备记录。**已写源码、安装成功、完整流程跑通、用户接受画质是不同状态。**

本次没有运行自动测试、模拟器、训练样例、真实重建或浏览器验收，没有上传房间，没有连接学校 GPU。只按更新手机的请求完成了安装所需的 Release 编译、签名和同应用覆盖安装；记忆与网页功能没有做运行验收。

## 1. 现在的结论

1. **OOOSplat 的适配代码已经接入主工作台，但还没有完成这台机器上的端到端实际接通。** 新入口是“手机采集 · Mac 重建”；支持照片文件夹交接、手工导回标准 PLY，以及有条件的本机 MCP 任务连接。
2. 本次在三个程序预设位置均未发现 OOOSplat.app：项目 vendor、Lexar/Applications、系统 Applications；也没有找到新交接任务记录。如果你装在别处，可以自己打开；自动“打开 OOOSplat”按钮只认这三个位置。
3. **手机已更新为 MemoryRoom采集 0.5.0（build 5）**，仍使用 local.memoryroom.capture，同一开发团队覆盖安装，未卸载旧 App。构建和安装成功不代表新引导与成片质量已经通过实拍。
4. 默认路径是手机采集 → Mac 整理原图 → OOOSplat 配准相机并训练高斯 → 导回 MemoryRoom → 布置内容与保存。
5. 学校 A40、手机本地训练、商业生成 API 是预留或计划，不是已经可点即用的生成后端。
6. 手机当前仍主要负责采集。空间库、网页、记忆编辑与模型操作主要在 Mac 本地工作台，不是此次已打包进手机的全部功能。

## 2. 核心链路与你理解的 GPU 顺序

~~~text
手机扫描
  ↓
.capture.zip：照片 + 相机参数/位姿 + 可用深度 + 拍摄记录
  ↓
Mac 工作台整理：保留原件，输出按时间排序的原尺寸照片
  ↓
选择计算路径
  ├─ 当前主入口：OOOSplat → 照片特征/相机配准 → 高斯训练 → 标准 PLY
  ├─ 旧入口：ARKit 位姿 + LiDAR 初始化 → Mac Brush → 房间包
  └─ 后续：学校 GPU / CUDA 执行器（尚未接通）
  ↓
统一场景包：模型、物品编号、布局、状态、记忆内容
  ↓
Three.js + Spark 查看器 → 查看/布置/记忆 → 保存版本
~~~

**通常不需要先在 Mac 得到高斯结果，再送学校 GPU“训练一遍”。** OOOSplat 的生成本身已经包含训练。以后若用 A40 加速，应在重建之前选远端路径，把原始照片、必要参数/遮罩和作业配置送过去，再取回模型。

也可以为比较效果用同一份采集分别跑两条路线，但这是两个独立作业。仅有最终 PLY 不保证能够完整恢复优化器、相机或继续训练，必须保留照片和项目数据。

当前 OOOSplat 路线重新从照片求相机，**没有自动使用我们保存的 ARKit 位姿、内参或 LiDAR 深度**。这些资料仍然保留。导回后的 COLMAP 模型尚未自动与 ARKit 坐标配准，真实尺寸和朝向不能直接视为准确。

## 3. 当前功能核对表

“源码已实现”表示本次能定位到相应代码，不等于已实际验收。

| 模块 | 当前实现 | 边界与状态 |
|---|---|---|
| iPhone 扫描 | 局部区域/整间房、真实照片、位姿、可用深度、拍摄记录、导出 | 最新源码已编译安装；新引导待用户实拍 |
| 扫描引导 | 红橙绿表面格、建议补拍格、速度/曝光/追踪/重叠提示、左右/高低计数、准备与细节清单 | 规则是启发式，不保证完整/清晰 |
| 照片交接 | 选择有效 room 帧，按时间排序，原字节复制，缩略图、交接记录 | 不训练；不混入物品/空位/放回段 |
| OOOSplat 手工入口 | 打开照片文件夹、打开已安装应用、导回标准 PLY、另存新房间包 | 本机未发现预设位置的应用；尚未端到端运行 |

| 旧 Brush 路线 | 仍保留旧任务与本地生成代码 | 上次真实335帧任务有成片文件；不证明新OOOSplat路线 |

| 观察与关节 | 独立模型拿起/旋转/归位；手动滑动/铰链/支点；父子跟随与开合显示条件 | 须先有独立部件；不是自动家具分解或物理仿真 |
| 记忆内容 | 标题、正文、时间文本、标签、照片/音频/视频/PDF、网页链接、录音、固定提问 | 文本筛选，未接LLM/转写/向量检索；网页是链接，不是网页存档 |
| 空间库 | 多空间、名称、另存副本、完整快照、历史版本、基础保存冲突 | Mac本地单用户；不含云同步、账号或多人共享 |
| 独立物品工作台 | 导入已有独立模型、输入变换、组装新版本 | 没有自动分割/训练/背景修复；独立页无3D拖拽预览 |
| 学校 GPU | Provider类型、任务计划存档、技术估算 | 无SSH/VPN/调度器/上传/训练执行器 |
| 手机本地/API | 协议与状态声明 | 没有相应执行器 |

模型与附件合计上限256MB；单记忆附件20MB。新手机采集交接入口上限8GB，解包仍有8GB/40,000条目等限制。旧生成入口的上传上限仍为1GB。超大模型分块/流式读取尚未实现。

## 4. 现在适合扫描什么

| 对象 | 现在可以做 | 暂时不能当成已经做到 |
|---|---|---|
| 书桌、墙角、柜体、床、沙发、椅子等静态区域 | 作为空间背景采集并重建 | 背景里的每件东西自动能拿走 |
| 一间静止的小房间 | 分多个观察位置拍墙地家具，再重建 | 只转一圈就保证所有家具背面和内部完整 |
| 合上的书、盒子、不透明摆件 | 记录其外观；也可另外记录物品片段 | 物品片段自动成为独立模型、可翻书页 |
| 柜子/抽屉 | 静止状态采集；另行分段保留不同状态素材 | 关上/打开混在房间帧中自动推断关节 |
| 玻璃、镜子、光亮金属、细椅腿、电线 | 可以拍到并备注困难区域 | 稳定忠实恢复透明/反光/细结构 |
| 走动的人、宠物、被移动的物品 | 建议等静止或避开 | 用静态训练准确恢复运动过程 |

本次建议先扫“书桌 + 后墙 + 邻近家具”的明确区域。整间房模式可以用，但最终可加载范围、细节和耗时仍受设备与模型体积限制。

## 5. 手机更新后怎么开始

这次已覆盖安装，无需先删除旧 App。

1. 在 iPhone 打开“MemoryRoom采集”。
2. 空间名称写明这次范围和日期，便于区分多次采集。
3. 先选“局部区域”，保留“只扫描空间（推荐）”；关闭“使用演练数据”。
4. 点击“新建并进入采集”。
5. 勾选“镜头已擦净，光线稳定，家具和门保持不动”。这是房间开始记录的条件。
6. 等追踪稳定，点“开始扫描”。
7. 若想采物品分段，可关闭“只扫描空间”，依次记录房间、物品、空位、放回。但当前主入口只拿room照片做房间，其他片段仅保留供后续；这次先不增加这些步骤。

iPhone当前采的是ARKit相机帧，不是系统相机48MP照片。保存JPEG质量为0.95，仍是有损编码；照片交接不会再缩放/重编码。

## 6. 局部区域怎么拍

1. **在目标正前方开始。** 同时拍到书桌和周围有纹理的边角，不只盯一面白墙或一个杯子的局部。
2. **先向左侧移，再向右侧移。** 手机持续看着目标；身体移动带来不同观察位置。相邻画面保留明显共同内容。
3. **抬高一点，再降低一点。** 看到顶部、前侧、桌沿和低处；变化要平缓，不突然甩镜头。
4. **看橙色格，换位置观察。** 不要靠来回晃动或原地旋转刷数字。
5. **看实际画面是否清晰。** 可关闭“显示表面覆盖”，检查原始相机预览；桌腿、边缘、反光和无法到达的背面写备注。
6. 达到基本条件后可以完成，有建议时可以继续补拍或确认先结束。不要为了所有格子变绿无限录制。
7. 点“打包采集”，通过隔空投送或存储文件转到Mac。

局部模式基础结束条件为至少30个有效视角；引导会建议更多左右/高低观察（代码中45等数量属于建议）。数量足够不保证质量，左/右也只是相对于第一张有效视角的位置。

## 7. 整间房怎么拍

- 从门口或容易认的位置开始，沿可走路线慢走。
- 一段一段拍，让墙角、门框、家具和地面连接起来。
- 走到新区域前保留上一块的共同边角；不要隔着房间突然对准另一面纯白墙。
- 补高处、低处、家具侧面，最后回到起点附近。
- 门、抽屉、椅子保持同一状态；挪东西前先暂停，并把变化记录成另外片段。
- 不要求攀爬、跨障碍或绕到无法到达处。真实缺失写备注。
- 基础结束条件为60个有效视角；全屋结构、100视角、路线和回起点等仍作为建议，不是永远不能结束的硬拦截。

不需要为追求张数不断重复同一视角。照片越多，配准和训练工作也可能越多。手机中断后可以找回已有记录并导出；不能假设新AR会话无缝接回旧坐标。

## 8. 颜色、方向和提示怎样理解

| 屏幕反馈 | 含义 | 该怎么做 |
|---|---|---|
| 红格 | 发现了位置，尚未记录足够有效观察 | 正常接近，让它与周围边角一起入镜 |
| 橙格 | 有观察，但多角度还不够 | 身体侧移，换观察位置 |
| 绿格 | 至少三个有效观察，并达到规则中的位移和角度条件 | 转向下一块，必要时补不同高度 |
| 放大的格子 | 当前建议补拍处 | 看方向提示，对准后侧移 |
| 无色 | 未发现、不可见、被遮挡或提示容量限制 | 不能理解为已经扫描完整 |
| 左/中/右，高/中/低计数 | 相对于起拍位置已保存过的相机位置 | 确认真的看到了目标对应面，不只追数字 |
| 物品12方向环 | 相机到过的绕拍方位 | 不是物品识别、分割、6DoF跟踪或完整度证明 |

覆盖格记录已观测表面；最多4,000个实际表面格、画面优先显示附近最多700个。达到容量会提示，后续未着色区域仍可能缺失。发现新表面后比例下降并不表示照片丢失。

常见提示：

- “先让跟踪稳定”：对准门框或家具边角，缓慢移动。
- “等待 LiDAR 深度”：先对准普通家具；持续没有深度时保留记录反馈，不要盲扫。
- “慢一点，画面会糊”：稳住后小步移动。
- “这里太暗”：开灯再回到该区域。
- “亮部丢失太多”：避开直射窗户和灯，保持光线稳定。
- “距离或表面不合适”：退开过近物体，避开镜面。
- “画面缺少可识别细节”：让边角和纹理一起入镜。
- “和上一位置接不上”：退回刚才的区域，再缓慢侧移。
- “这个位置已经记录”：换一个位置，不只原地转动手机。

不合格帧不会增加有效视角；暂停或只看预览也不会刷绿。以上规则目前未用这次新版实拍校准。

## 9. Mac 如何运行新主链路

### 9.1 先准备OOOSplat

目前默认程序位置未找到它，需要先从官方发行页安装适合Apple Silicon Mac的版本：

https://github.com/ooolabdev/ooosplat/releases

程序可放在 /Volumes/Lexar/Applications/OOOSplat.app；具体系统要求与功能以所装发行版本为准。将项目目录设为：

~~~text
/Volumes/Lexar/MemoryRoom/data/processed/ooosplat-projects
~~~

这一步只是安装和配置，不能证明实际素材一定重建成功。当前没有替你自动下载或安装第三方应用。

### 9.2 第一次先用文件夹交接

1. 双击项目根目录“启动工作台.command”，打开 http://127.0.0.1:4317/ 。
2. 点击“手机采集 · Mac 重建”。
3. 导入新.capture.zip，点“整理照片，交给 Mac 重建”。这一步仅解包/整理，不启动训练。
4. 点“查看照片”，检查这次实际拍到的范围与清晰度。
5. 点“打开照片文件夹”，在OOOSplat新建**普通图片**任务，选其中images文件夹。
6. 若OOOSplat询问图片顺序，选“已按拍摄顺序排列”；先用均衡档和自动优化。
7. 保持Mac、移动硬盘和OOOSplat运行，不要同时启动旧Brush任务争用资源。
8. 完成后找到本任务final.ply，或导出标准binary little-endian高斯PLY。
9. 回MemoryRoom对应任务，选择文件并点“导回所选模型”。
10. 点“打开新的空间预览”，确认朝向和大小，满意再“保存到硬盘”；可另导出.room.zip备份。

新入口对原始房间照片按时间编号，不再缩放/重新编码，但OOOSplat内部仍会按自身配置处理图片。

**格式边界：** 此交接入口只收标准binary little-endian高斯PLY；不是ASCII/压缩PLY/普通点云。模型与附件合计256MB，过大要保留原项目并精简导出。独立模型的一般导入入口支持更多格式，不能混淆两个入口。

### 9.3 MCP自动交接是可选项

首次建议先完成文件夹方式。有支持MCP的OOOSplat版本后：

- 在“设置 → MCP”启用本机默认39877端口。
- 授权输入目录 /Volumes/Lexar/MemoryRoom/data/processed/mac-reconstruction 。
- **先**把OOOSplat项目目录设到上述Lexar位置，再创建任务。
- 在MemoryRoom点“连接 OOOSplat 并开始均衡重建”，完成后“导回已完成的OOOSplat模型”。

源码已有连接、提交、进度、停止与导回，但尚未用本机实际安装版本验证。工具名称与官方MCP文档相符，不等于所有返回字段/版本兼容已经实测。不要在连接超时后反复新建付费或计算任务；先去OOOSplat查看已有任务。

官方接口文档：
https://github.com/ooolabdev/ooosplat/blob/main/docs/mcp-v1.md

## 10. 模型导回后，可以怎样用记忆系统

现在不必等AI访谈实现：

1. 导入/打开房间，切换到布置模式。
2. 添加记忆点或容器，把文字内容绑定到某个位置；它是用户标记，不伪装成已经分割的真实物品。
3. 在“记忆”中写标题、故事、时间和标签，添加本地照片、音频、视频、PDF或网页链接。
4. “保存卡片到当前空间”后，再点主界面“保存到硬盘”。
5. 在“空间库”打开历史版本，或另存为不同空间。
6. 有真实独立模型时，选中原节点并“替换为真实模型”，可保留物品ID、记忆和交互设置；尺寸与位置仍需确认。

网页目前是外部链接，没有自动归档历史网页；录音不会自动转写，固定问题不会自动生成用户经历。PDF暂为下载，尚无完整翻书阅读器。

若已有独立门/抽屉模型，可以手动设置关节、父子关系和“打开后显示”。**整屋高斯里的柜门不会因此自动消失或被切出来**，背景去重和内部几何还需另做。

## 12. 下一步实现顺序

1. **先完成一组真实新链路成片。** 安装OOOSplat、交接原图、生成、导回、保存，记录实际画质与各阶段时间。
2. **解决坐标与尺度。** 把COLMAP结果与ARKit/实测尺度对齐，否则独立资产不能可靠放回。
3. **单物品闭环。** 选目标 → 分割/遮罩 → 独立网格或高斯 → 位置确认 → 拿起归位。
4. **干净背景。** 利用空位补拍真正去掉旧物品和残影；不能只叠加独立模型。
5. **真正家具部件。** 独立门/抽屉、内部表面、轴与行程、碰撞代理；已有手动交互框架可以承接。
6. **学校A40执行器。** 明确学校权限、环境、传输、任务调度、日志、取消、恢复与结果格式后再接；不是现在已经有一键远程训练。
