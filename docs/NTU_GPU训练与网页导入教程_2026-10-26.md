`COMPLETED` 加上 `environment/installation-finished.txt` 才表示安装脚本执行结束，仍不代表房间重建成功。`FAILED`/`TIMEOUT` 时先看日志，不提交训练。

安装/首次训练需要访问官方包源和模型权重地址；学校计算节点若禁止外网，需要按学校允许的方式准备离线依赖或请管理员协助。不要为了下载把训练移回登录节点。Splatfacto 初始化可能下载 LPIPS/AlexNet 等公开权重，即使关闭自动评估也可能发生；这不是上传你的照片，也不是付费 API。

## 七、第四步：提交真正的房间训练

安装完成后，在**学校终端**：

```bash

```

记录这次的训练作业编号。作业依次做：

1. COLMAP 从照片恢复相机与稀疏点。默认顺序匹配，适合这批连续有序采集；不是任意无序相册的通用设置。
2. 输出 `registration-report.json`：493 张中有多少成功注册。初始规则是低于 70% 就停止以免继续消耗 GPU。**70% 只是待校准的成本门槛，不是画质标准；超过它仍可能有漂浮和缺失。**

## 八、怎样知道训练好了、结果是什么

在**学校终端**：


每次运行会建立含 UTC 时间与作业编号的独立结果目录。例如路径结构：

```text
cap_1ebc5b7a/
  images/                             原始训练照片
  processed/transforms.json           COLMAP 相机结果
  processed/colmap/                   稀疏重建、数据库等
```

**训练成功、PLY 导出成功、网页加载成功、视觉质量好，是四件不同的事。** 首次结果主要由你实际观察：原位置附近是否像原房间，墙角是否稳定，家具是否重影，地面是否缺失。暂未执行或声称自动画质验收。

## 十、第六步：放进现有本地网页

1. 打开移动硬盘里的 MemoryRoom 网页工作台；已有服务可访问 `http://127.0.0.1:4317`。若服务未启动，在 Mac 项目目录执行 `npm run dev`，不用重新训练。
2. 当前场景有需要保留的内容，先“保存到硬盘”。建议点空间列表的“＋”建立空场景，用于这次新房间。
3. 点主界面的 **“导入模型”**，选刚下载的 `memoryroom.ply`。
4. “作为”选择 **“房间背景 · 固定显示”**；名称填“本次扫描的房间”。不要把整间房作为可拿起的小物品。
5. 坐标单位先选 **“米 / 保留原始尺度”**，含义是保持导出数值，并不证明本次模型是真实米制。
6. 查看整体方向。Nerfstudio 导出约定为 Z 轴向上，当前场景按 Y 轴向上使用；若导入后侧躺，可在节点变换中先尝试 X 旋转 **−90°**。以实际显示为准，若导入器已转换方向就不要重复旋转。此处变换整个高斯对象，不应只改 PLY 的点坐标而漏改高斯旋转。
7. 大小与朝向需要手动校正，完成后“保存到硬盘”。用当前场景导出功能可保存 `.room.zip`，其中才包含场景布局和记忆内容。

导入入口支持普通高斯 PLY，故不需要冒充 OOOSplat 任务。不要在 OOOSplat 专用任务表里强行绑定学校结果；此路线目前没有实现自动取回与任务登记。

**容量限制：** 当前项目模型和附件合计上限约 256 MB。30,000 步不保证模型小于此值；减少球谐阶数也不保证一定够。若超过上限，先保留完整 PLY，不要强行导入或直接提高限制。后续需要针对 Spark 支持的格式做压缩/裁剪副本，并实际检查画质和手机内存。模型文件更小也不等于手机一定流畅。

## 十一、常见情况与恢复方式

### 已遇到：COLMAP 阶段被终止，内存超过申请量

作业 47028 的 step MaxRSS 为 49.19G，申请为 28G，17 分钟后被终止，未到 5:50:00 时限。记录为 FAILED / SIGKILL、Reason None；强烈指向内存限制相关终止，尚无调度器明确 OOM 结论。

当前本地脚本增加 `colmap-limited.sh`，通过 `--colmap-cmd` 显式限制特征提取、匹配和 mapper 为两线程，匹配上限从默认 32768 收紧为 8192；不降低原图分辨率，也不增大账户申请上限。该匹配上限可能影响复杂图像对，注册率和实际画质仍需观察。启用 `--verbose` 输出 COLMAP 子进程进度；训练阶段的 CUDA 编译并发也降为 2。

旧学校目录需要同步 wrapper 和 run_remote.sh/train.sbatch 的修改。未完成的 `processed/` 应先重命名保留，再重新运行；旧版 Nerfstudio 包装器重建时会重建 COLMAP 数据库，这不是自动续用旧匹配结果。依赖与原图无需重新安装或上传。

参数来源：[COLMAP 3.8 CLI 选项](https://github.com/colmap/colmap/blob/3.8/src/util/option_manager.cc)、[3.8 SIFT 默认配置](https://github.com/colmap/colmap/blob/3.8/src/feature/sift.h)。源码核对不代表实际内存已降至 28G 以下；修复后须看真实作业记录。

### 已遇到：Unrecognized arguments: False

训练作业 47026 在参数解析时退出，没有开始照片处理。当前布尔选项使用 `--no-gpu` 关闭 COLMAP GPU，不能写 `--gpu False`。本地执行脚本已修正；学校此前上传的旧副本可运行：

```bash
cd ~/memoryroom/jobs/cap_1ebc5b7a
sed -i 's/--gpu "\$COLMAP_GPU"/--no-gpu/' run_remote.sh
sbatch train.sbatch
```

这只改变 COLMAP 的特征提取/匹配设置，高斯训练仍使用 GPU。无需重新下载环境。旗标格式参见 [官方 CLI](https://docs.nerf.studio/reference/cli/ns_process_data.html)。

### 已遇到：fpsample 缺少 scikit_build_core.build

实际登录节点安装已完成 CUDA/PyTorch，但 Nerfstudio 依赖 fpsample 1.0.2 的元数据生成失败。原命令 `--no-build-isolation` 阻止 pip 自动准备其构建后端；不是需要再下载一次 CUDA。当前安装器已去掉此选项。旧包用户可在学校登录节点仅重试以下阶段：

```bash
module load anaconda/25.5.1
eval "$(conda shell.bash hook)"
conda activate memoryroom-ns115
cd ~/memoryroom/jobs/cap_1ebc5b7a
export PIP_CACHE_DIR="$HOME/memoryroom/cache/pip"
export MAX_JOBS=2 OMP_NUM_THREADS=2 CMAKE_BUILD_PARALLEL_LEVEL=2
BUILD_NO_CUDA=1 python -m pip install -c constraints.txt 'nerfstudio==1.1.5' 2>&1 | tee logs/install_nerfstudio.log
```

该阶段仍要下载 Nerfstudio 的其他依赖，不能承诺没有后续下载；已安装的同版本 CUDA 和 PyTorch 无需重装。成功后按前文下载公开 AlexNet 权重，再提交训练。原完整 CUDA Toolkit 包含调试、分析、可视化工具，3.18 GB 不是本项目最小 CUDA 依赖规模；当前已安装，先保留，不在恢复安装途中更换 CUDA 路线。

依据：[fpsample 构建配置](https://github.com/leonardodalinky/fpsample/blob/main/pyproject.toml) 声明 `scikit-build-core>=0.11` 与 `pybind11>=2.6`。上述恢复命令尚待实际执行，不表示 Nerfstudio 安装已通过。

### 已遇到：学校 Conda 的 Qt 初始化报 unbound variable

首次安装作业 47019 因 `qt-main_activate.sh` 读取未设置的 `QT_XCB_GL_INTEGRATION` 退出。原因是调用脚本开启 `set -u`，不代表 CUDA 或照片出错。当前本地脚本和上传包已修订；此前已上传的学校副本，在学校终端执行下面命令后重提，无需重传照片：

```bash
cd ~/memoryroom/jobs/cap_1ebc5b7a
sed -i 's/^set -euo pipefail$/set -eo pipefail/' setup.sbatch install_env.sh train.sbatch export.sbatch
sbatch setup.sbatch
```

保留 `-e` 与 `pipefail`，安装命令真正失败时仍会退出。修复后的远端执行结果尚未确认。

| 现象 | 含义与下一步 |
|---|---|
| `PENDING` / `PD` | 正在排队，查看原因；不代表脚本已开始跑 |
| 安装作业失败 | 看 `setup_编号.err`；常见是计算节点联网、Conda 依赖或空间问题。不要先改成系统级安装 |
| module 找不到 | 历史模块名可能已变，用学校模块列表查实际 Anaconda 名称 |
| gsplat 编译失败 | 保存首段错误和环境记录；检查 Toolkit/nvcc、编译器和 PyTorch CUDA 版本，而不是照着 `nvidia-smi` 的版本盲装 |
| COLMAP Qt/display 错误 | 脚本已设置无界面模式；若仍报错，需要对应无头 COLMAP 构建或系统依赖，不能靠开浏览器解决 |
| COLMAP 注册率低 | 图像衔接、模糊、纹理/反光、相机或匹配策略可能有问题；看注册报告和日志，增加高斯步数不能修复缺失的相机轨迹 |
| GPU 显存不足 | 先改训练数据解析器的 `--downscale-factor 1` 为 `2` 再提交新训练，代价是细节减少；不要马上把全局内存上限拉高 |
| 主机内存 OOM | 看 Slurm 记录；减小图像分辨率/数量或按学校额度调整资源，显存和主机内存是两种限制 |
| 六小时到，`TIMEOUT` | 队列强制结束；本次没有自动抢救导出承诺。使用已有检查点继续训练或另交导出作业 |
| PLY 有但没有 `EXPORT_COMPLETED.txt` | 可能中断在导出途中，或只是部分检查点导出；看日志，不作为完整训练结果 |
| 房间漂浮、重影、空洞 | 可能来自相机错误、动态物体或缺少视角；先定位来源，再决定补拍/调整匹配或训练，不默认让 AI 手修模型 |

### A. COLMAP 中途超时，还没生成 transforms.json

脚本为了避免覆盖，会拒绝复用不完整的 `processed/`。先保留而不是删除：

```bash

mv processed "processed-incomplete-$(date +%Y%m%d-%H%M%S)"
```

这只是保留证据，直接重提会从相机重建阶段重新开始；如果仍超时，需要专门做 COLMAP 恢复/阶段拆分或改变匹配策略，不能无限重复同一作业。

### B. 已有训练检查点，只想先导出看看

在学校找原始配置：

```bash

```

把实际找到的**原始** `config.yml` 绝对路径填到下面（不要用结果目录里的 `config-reference.yml` 代替）：


这是申请短 GPU 作业导出最近保存的检查点，不是完成剩余训练。结果在 `results/checkpoint_新作业编号/memoryroom.ply`，标记为 `CHECKPOINT_EXPORT_ONLY.txt`。

### C. 从检查点继续到 30,000 步

找到原始配置旁边的 `nerfstudio_models` 目录，填入下面：

## 十二、这次成本和接下来反馈什么

- 不使用 Marble、Hunyuan、OpenAI 等付费 API，不需要买 OOOSplat 或公网云 GPU。
