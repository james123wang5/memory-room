## 一、扫描时现在怎样看

相机预览扩大，增加“显示表面覆盖”开关，可以随时切换原始画面和颜色标记。除了 RoomPlan 识别的墙面、地面，还用采集到的深度构建桌面、家具、物品表面的稀疏覆盖格。

| 显示 | 意义 | 下一步动作 |
| --- | --- | --- |
| 红色 | 已识别到几何位置，但还没有记录到合格视角 | 靠正常可走路线接近，让它与周围边角一起入镜 |
| 橙色 | 记录过，但多角度还不足 | 侧移身体，换角度拍；不要只转手机 |
| 绿色 | 至少三个有效视角，并存在足够位移和角度差 | 可以继续下一块，之后再换高度观察边缘 |
| 放大的格子 | 当前建议补拍处 | 对准它，小步侧移 |
| 没有颜色 | 可能未发现，或者暂时不在当前可见范围 | 不能据此认为扫完了 |

只有通过现有帧质量条件并正在录制时才增加覆盖。移动预览、暂停、模糊和重复位置不会把表面刷绿。跟踪不稳定时隐藏标记。用当前深度判断可见性，不把家具后面的墙面标记画到前方物品上。

覆盖以世界空间 18 厘米格划分，方向相反的面区分存储。实际表面最多 4,000 格，画面优先展示附近的最多 700 格；达到容量时明确提示，相机继续录制，不能把不着色区域视为完整覆盖。RoomPlan 的结构变化仍可能改变格子及覆盖比例。已发现更多表面时百分比也可能下降，这是分母增加，不是照片丢失。

绿色表示采集观察条件达到设定值，不表示重建清晰、所有背面完整或反光表面可恢复。这些阈值尚待用户实拍反馈。

### 建议操作顺序

1. 先开灯、擦镜头，把目标与周围有纹理的家具边角一起放进画面。
2. 开始记录，左右缓慢侧移，保持相邻画面有大幅重叠。
3. 看放大的补拍格：橙色就换一个位置观察，别站着转手机。
4. 再稍微抬高或降低手机，补顶部、侧面和边缘。
5. 房间路线回到起点，局部区域确认左右两侧和不同高度都拍过。
6. 完成后生成，再由用户看实际结果。

物品模式增加 12 格方向环和已到过的高度提示。开始时将静止的目标放在取景中央，系统使用中央深度估计绕拍中心；它不是实例分割或物品追踪。方向环只说明相机到过哪些方向，不代表每面均完整。中途不能拿着物品翻转，否则相机坐标不能直接用于当前重建链路。

## 二、参考了什么，采用了哪一部分

公开资料先用 Lightpanda 读取；GitHub 文件页面正文不完整时改读公开源文件。没有下载私有资料、账号数据或大型模型。

- [Scaniverse 扫描技巧](https://nianticspatial.com/docs/scaniverse/techniques/)：连续缓慢移动、视角重叠、多角度和不同高度观察、通过实时反馈发现缺漏。采用交互原则，没有取得或复制其私有算法。该文档也涵盖定位场景，不能把其中的 Site 或云服务当作本项目本地建模能力。
- [Apple：Meet Object Capture for iOS](https://developer.apple.com/videos/play/wwdc2023/10191/)：方向环、自动记录、环境及速度反馈，以及不可翻转物品的多高度拍摄。采用可见的方向与高度提示。本项目没有换成 ObjectCaptureSession，因而不是苹果内部的覆盖算法，也不使用它的“完成一次扫描”结果。
- [apple-spatial-capture 的 GaussianSplatCaptureView.swift](https://github.com/A7ALABS/apple-spatial-capture/blob/main/ios/apple_spatial_capture/Sources/apple_spatial_capture/GaussianSplatCaptureView.swift)：阅读自动采集、速度与预测模糊、跟踪提醒和位姿标记实现。
- [同项目 ObjectCaptureFlowView.swift](https://github.com/A7ALABS/apple-spatial-capture/blob/main/ios/apple_spatial_capture/Sources/apple_spatial_capture/ObjectCaptureFlowView.swift)：阅读准备、检测、拍摄、保存、重建的分阶段交互以及系统反馈转换。它通过 Apple 的 ObjectCaptureSession 获取完成状态，不能把这一状态直接搬到本项目的 ARSession 数据上。

这次按已有 ARKit / RoomPlan 采集代码重新实现覆盖格和方向环，没有复制上游源代码或整体引入 Flutter 插件，也没有改变当前照片、位姿、深度格式。

## 三、生成后：独立物品工作台

入口：项目根目录 `打开独立物品工作台.command`。

这是独立的本地页面 `http://127.0.0.1:4320`，不会启动或重启 4317 上的原工作台，也不会启动任何训练。尚未启动验证。沿用项目已有 Node / tsx 依赖。

1. 在原空间工作台下载已生成的 `.room.zip`。
2. 双击独立物品工作台入口，按窗口中的地址打开页面。
3. 选中房间包，再选择一个独立 GLB / 3DGS PLY / SPZ 模型。
4. 填写物品名字、房间内的位置、旋转角度和大小。位置使用米；模型自身可选米、厘米、毫米。
5. 说明背景是干净背景，还是仍有原物品。后者会在新项目内记录重影提醒。
6. 保存并下载新包，在原工作台打开它。独立节点复用已有观察、旋转和归位交互。

每次导出使用新的 revision，并记录 parentRevision；原房间包不覆盖。新增模型进入包内 assets，身份、单位、文字说明和变化记录一并保留。旧项目已有的说明、关节状态和节点不被本入口改写。

输出另存到 `data/processed/assembly/<版本编号>/scene.room.zip` 和 `assembly.json`。关闭服务前需导出；没有导出的组装状态只保留在服务内存里，刷新页面可恢复，关闭进程会丢失。

当前边界：没有此页内的 3D 拖拽预览；参数调整后导出到原查看器查看。加入模型不会去掉原背景中的物品。这里只支持内嵌贴图、无需额外压缩解码器的 GLB。组合包仍使用既有 256 MB 上限。生成结果标记为尚未用户确认。

## 四、独立物品数据准备工具

源码：`tools/objects/prepare.py`。这次只写工具，没有对用户的采集执行它。

`inventory` 读取原始 `session.json`，按物品列出 object / empty / placement 片段及图像清单；丢弃的旧片段、非正常跟踪帧不参与。只有 room 片段时返回空的物品清单，不虚构独立物品。

`prepare` 接收已经制作好的前景蒙版清单，按其选择物品视角。蒙版为与原图同大小的灰度图，白色保留、黑色排除。清单包含 `capture_id`、`object_id` 和 `masks` 字典；字典键是 session 中的 image 原路径，值是相对于清单目录的蒙版文件路径。仅明确确认物品静止后才能使用 `--stationary-confirmed`。清单不属于当前采集或包含别的片段时直接报告输入问题。

工具复制衍生素材到独立目录，输出：

- `input/`：选择后的照片、蒙版及衍生会话，原件不改。
- `dataset/`：透明背景图像、相机位姿、蒙版内的深度种子点和重建数据说明。
- `placement.json`：物品身份、源采集、米制单位及初始位置建议。

坐标中心同时作用于相机和平面点坐标，模型训练后的节点位置可从 placement.json 的 suggested_position_meters 取回。若物品在房间扫描之后移动过，这只是采集时的位置，仍须重新对齐。

输出在 `data/processed/object-preparation/<编号>/`。失败时仅清理该工具新建的临时目录，不清理原始数据。依赖沿用数据工具的 NumPy / Pillow。

开发入口用法：`python3 tools/objects/prepare.py inventory <session.json>`；制作好蒙版后用 `python3 tools/objects/prepare.py prepare <session.json> --object-id <编号> --mask-manifest <清单.json> --stationary-confirmed`。这些是工具的正式入口说明，本轮没有执行。
