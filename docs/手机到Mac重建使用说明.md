# 手机采集 → Mac 重建 → MemoryRoom

更新：2026-10-26。已按用户请求完成安装所需编译和签名，手机更新为 v0.5.0（build 5）。没有运行测试、样例、训练、新重建或浏览器验收。OOOSplat 三个预设程序位置仍未发现安装，也未运行新交接链路。最新操作与功能核对见 [当前教程](当前功能核对与手机扫描教程_2026-10-26.md)。下文为当前交接流程，不代表已实拍验证。

## 选用的主链路

手机 MemoryRoom（ARKit / RoomPlan 采集）→ 原始采集包 → Mac 整理房间照片 → OOOSplat 重新估计相机并训练高斯 → 标准 PLY → MemoryRoom 预览与保存。

OOOSplat 是桌面工具，处理输入照片或视频，并不是在手机上实时标出漏扫位置的采集 App。它提供使用说明、界面示例与桌面流程；手机的现场引导仍由我们的采集端承担。当前官方主分支的 Mac 说明使用 COLMAP 与 Brush 系列的 OOOBrush 运行时，Mac 仍标 Alpha，不能将主分支功能等同于所有发行安装包。参见 [官方仓库](https://github.com/ooolabdev/ooosplat)、[发行页](https://github.com/ooolabdev/ooosplat/releases)。

这次选择是为了复用更完整的桌面重建流程，尤其是照片间的相机配准；不是同素材比试后得到的画质冠军。原来的 Brush 配置也不是 Brush 的画质上限。糊片、反光、遮挡与缺少侧向视角，不会因更换工具自动消失。

## 手机要采集什么

| 内容 | 保存方式与作用 |
| --- | --- |
| RGB 图像 | 保留 ARKit 相机帧的实际像素尺寸；JPEG 保存质量从 0.85 调至 0.95。不是系统相机 48MP 静态照片模式，也不是无损编码。Mac 整理时不再次压缩或缩放输入照片。 |
| 拍摄顺序与时间 | 连续视角按时间排序，并生成补零文件名，交给桌面工具时顺序明确。 |
| 相机内参与位姿 | 每帧记录，保留原坐标；供后续配准、查问题及资产组装使用。 |
| 可用 LiDAR 深度 | 原始深度与对应记录一起保留；设备或帧没有深度时不能宣称完整。 |
| 已发现表面的覆盖 | 红格未记录、橙格需换角度、绿格已有多角度记录。未知或遮挡表面不等于已完成。 |
| 高低、左右视角与现场清单 | 相对第一张有效照片的位置计数；记录光线/静止确认、可到达范围确认、细节检查和缺失备注。 |
| 片段身份 | 房间、物品、空位、放回与作废旧片段分别保留，不能混进同一次静态房间重建。 |

当前 OOOSplat 入口使用照片重新求解相机，**并未接入 ARKit 内参、位姿或 LiDAR 的自动导入**。它们在采集包和交接记录中保留，不意味着 OOOSplat 已使用这些信息。

## 现场怎么拍

1. **先选明确范围。** 本轮建议一片书桌、柜体和相邻墙角作为成片目标。擦镜头，保持室内光线稳定，不在一段扫描中开关门或移动家具；确认后才能开始记录。
2. **目标中央起拍，移动身体。** 先让目标和邻近有纹理的边角一起入镜，再向左右小步侧移。相邻画面保留大量共同内容，不要只站在原地转动手机。
3. **再补高低视角。** 在可站立的范围抬高或降低手机，看顶部、侧面和低处。视角计数只是记录到过的位置，不是表面完整度；数字够多也不能替代观察。
4. **沿提示补扫。** 慢一点、暗光、过曝、跟踪不稳时调整拍法。对于橙格，用身体侧移形成不同视角。新发现表面会让覆盖比例下降，这是正常现象。
5. **检查边缘和困难处。** 玻璃、镜面、光滑纯色板、细椅腿或无法到达的背面写入备注。不要为了把所有格子变绿反复晃动手机，或跨越障碍。
6. **完成后打包。** 通过隔空投送或“存储到文件”带到 Mac。原始图片、位姿、深度与现场记录保留在采集包中。

整屋则沿可走路线拍摄，再回到起点，补拍墙角、地面和家具侧面。多拍大量重复照片不等于更完整，还会拖慢配准。参考 [Scaniverse 官方采集指南](https://scaniverse.com/support/) 与 [Apple Object Capture 采集指导](https://developer.apple.com/videos/play/wwdc2023/10191/)，本项目的阈值和提示仍待用户真实使用反馈调整。

## Mac 上的操作

### 首次准备

- 从 [OOOSplat 官方发行页](https://github.com/ooolabdev/ooosplat/releases) 选择 Mac Apple Silicon 版本；官方当前说明要求 macOS 15 或更新版本。本轮没有安装第三方软件。
- 将其项目目录设到 `/Volumes/Lexar/MemoryRoom/data/processed/ooosplat-projects`。照片、模型和后续处理保留在移动硬盘。
- 工作台“打开 OOOSplat”会查找本项目 `vendor/OOOSplat.app`、`/Volumes/Lexar/Applications/OOOSplat.app` 和 `/Applications/OOOSplat.app`；其他安装位置请自行打开。

### 文件夹交接（默认）

1. 在工作台选择“手机采集 · Mac 重建”，导入 `.capture.zip`。原件另存，素材整理不启动训练。
2. 查看照片缩略图和采集记录。整理阶段仅检查格式、文件与图像尺寸等必要条件，不做画质打分或自动成片验收。
3. 点击“打开照片文件夹”，在 OOOSplat 新建普通图片任务，选其中的 `images` 文件夹；询问顺序时选已按拍摄顺序排列。
4. 从“均衡”档开始，并开启自动优化。按官方当前说明，其预算高于我们此前 6000 步、1024 长边、40 万高斯的简化配置；具体设置以所装版本显示为准。不要同时启动旧 Brush 任务和 OOOSplat 争用内存。
5. OOOSplat 完成后，将本次任务的 `final.ply` 或导出的标准 binary little-endian 高斯 PLY，导回工作台对应记录。ASCII、压缩 PLY 或普通点云不是这个入口的输入格式。
6. 打开新空间预览，确认画面后再点保存。生成和导回各自保留文件，不会自动覆盖当前已保存的空间。

COLMAP 输出尚未配准到 ARKit 米制坐标。新模型导回时显式标记尺度和朝向未知；可通过现有组装与变换功能调整，不能直接假设它与旧房间或物品的位置、尺寸一致。本轮没有完成自动配准。

### 可选的本机任务连接

如果安装版本有“设置 → MCP”，可开启默认端口 `39877`，并授权本项目 `data/processed/mac-reconstruction` 作为输入目录。先设置项目保存目录，再从 MemoryRoom 点击连接并开始均衡重建。

接入代码依据 [OOOSplat 官方 MCP 文档](https://github.com/ooolabdev/ooosplat/blob/main/docs/mcp-v1.md)：提交、读取阶段进度、停止本次任务、导回完成模型。只访问本机默认端口，不调用云服务；重新连接读取原任务，不擅自重试失败训练。没有该功能的发行版本直接走文件夹交接。

关闭工作台弹窗不会停止已交给 OOOSplat 的任务；关闭 OOOSplat 本身则可能中断。进度中的百分比属于当前阶段，不当作全程百分比；只有应用提供 ETA 时才显示。重新打开历史记录可继续查询；失败或停止的任务须在 OOOSplat 里明确处理。

## 时间应该预留多少

| 场景 | 当前可用信息 |
| --- | --- |
| 旧包：335 个房间视角 | 读取已有任务记录得到，从开始到完成约 **11 分 29 秒**。这是旧 ARKit → Brush 简化路径，不能当作新流程的速度或画质承诺。 |
| M1 Pro / 16 GB，局部区域 | 新流程先预留 **1–3 小时**。仅为安排时间的粗预算，没有在本机运行 OOOSplat 得到测量。 |
| M1 Pro / 16 GB，整间房 | 先预留 **3–8 小时或更久**。照片数量、匹配难度、CPU 配准、模型规模与内存都会影响结果。 |

总耗时包含传输、解包整理、照片特征与相机配准、高斯训练、导出和导回。新链路增加照片配准，同时提高重建预算，不能拿旧版十几分钟直接外推。首次实际运行的 OOOSplat 日志才是缩小估计范围的依据。

## 椅子与独立物品

房间扫描时椅子不动。需要可搬走的椅子时，记录原位置与真实尺寸，移开后补拍地面/墙面，再在空旷位置单独绕拍椅子，之后组装回去。默认保持椅子静止、手机绕拍；需要翻转拍底面时拆成独立片段，不能把移动中的椅子混进房间重建。

无法拍到的底面或背面应明确记录缺失；后续可采用人工简化几何或带说明的生成补全，不把推测当成真实扫描。独立物品后续优先考虑 Apple Object Capture 贴图网格，详见 [路线选型与椅子扫描](research/2026-10-25_重建路线选型与椅子扫描.md)。当前物品工作台能导入与组装独立资产，但自动分割、物品训练、背景去除和配准仍未完成。

## 文件与当前边界

- 原始上传：`data/raw/mac-imports/<任务>.capture.zip`。
- 交接目录：`data/processed/mac-reconstruction/<任务>/`，含 `capture/` 原件、`input/images/` 未重压缩房间照片、`thumbs/`、`handoff.json`、`prepare.log` 和任务状态。
- OOOSplat 项目：`data/processed/ooosplat-projects/`，由用户在应用中设置。
- 导回结果：交接目录内每次单独保留一个版本的 `.room.zip`；满意后才写入当前项目。
- 原始采集入口上限 8 GB，现有项目包上限 256 MB；较大模型须精简导出，流式大模型导入尚未实现。
- 如果素材整理时退出服务或断开硬盘，保留原件和日志，重开后检查历史；未整理完成的任务可重新导入，当前没有自动续解包功能。
- 只完成输入与交接链路代码，并未承诺“拍全”或“无 Bug”。新手机引导现已安装，OOOSplat 的预设位置未发现安装、新链路未执行。用户后续用真实素材决定画质是否满足需求。
