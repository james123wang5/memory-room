# MemoryRoom：免费开源手机高斯重建选型

调研日期：2026-10-26。用户最新约束：不接受 Scaniverse 的付费/三天试用入口，优先源码公开、可免费自行构建、尽可能快速且效果好的方案。本文以这一约束取代此前“优先使用 Scaniverse”建议。

本轮使用已配置 AnySearch MCP 检索，Lightpanda 提取公开项目和官方正文；PocketGS 的 arXiv 抓取失败时回退内置网页读取。没有安装新引擎、编译、训练、上传房间或改动应用代码。候选排序是适配判断，不是同一房间实测画质榜。

## 1. 当前建议

保留两条免费开源路线，统一输出给现有 Three.js / Spark / Scene Graph：

**手机自主路线：**现有 iOS 采集器 / 参考 apple-spatial-capture 原生采集代码 → 手机相机位姿与深度点 → 训练数据适配 → frs0n/msplat-ios Metal 训练 → PLY/SPZ → MemoryRoom。

**电脑可控路线：**手机采集或规范全景素材 → OOOSplat / 同源 Brush → PLY/SPZ → MemoryRoom。学校 GPU 路线保留；不因本次调研修改已完成的任务或默认更换引擎。

目标是缩短用户操作、减少独立环境配置，并保留自有交互/记忆系统。不能承诺仅换训练引擎就修复采集缺失、相机漂移、反光或家具背面缺失。

## 2. 为什么先排除 Scaniverse

用户实际看到三天试用/付费门槛，因此不把它作为默认入口，不要求购买。官方当前 App Store 文案仍称 Classic 设备端 Gaussian 捕获/处理不限次数免费，与用户所见入口存在差异；本轮没有查看用户手机界面，不推断是哪个应用或哪个模式。产品路线不依赖澄清这一差异。

即使某个入口可免费导出，Scaniverse 本地训练核心仍不是可以搬入 MemoryRoom 的开源引擎；SPZ 格式开源与扫描 App 开源是两回事。Niantic 的网站重建、VPS/NSDK 与经典手机模式也不能混称同一免费能力。

来源：[开发者 App Store 说明](https://apps.apple.com/us/app/scaniverse-3d-scanner/id1541433223)、[Niantic 平台说明](https://www.nianticspatial.com/en/blog/scaniverse)、[开源 SPZ](https://github.com/nianticlabs/spz)。

## 3. 最值得集成的手机开源组件

### frs0n/msplat-ios：优先审查的 iPhone 训练引擎

[仓库](https://github.com/frs0n/msplat-ios)当前可访问，README 标明 Apache-2.0、iOS 构建和内存受限优化，提供 Swift API 与 iOS 示例。本次发现纠正了早期资料中“该分支检索不到，因此不采用”的状态，不能继续把那一历史状态当作当前事实。

- Metal 训练，不依赖 CUDA；可放进 iPhone 原生应用。
- 增加有界图像缓存、临时缓冲区控制、训练高斯增长限制等手机相关处理。
- 接收 COLMAP binary/text、Nerfstudio、Polycam 格式；输出 PLY/SPLAT/SPZ。
- 当前说明要求 macOS15+ / Xcode 来构建，iOS目标18.0。XCFramework 是从仓库构建的产物，不是只拿示例工程就自带完整构建结果。
- [示例 README](https://github.com/frs0n/msplat-ios/blob/main/examples/ios/README.md)明确是“导入已配准的 COLMAP 数据集 → 手机训练 → 分享 PLY”，没有完整房间扫描和自动质量引导。

因此最适合作为我们的训练内核，不能称它是可直接下载的完整 Scaniverse 开源替代 App。README中的性能/内存数字有特定数据集和配置，不是本项目整屋 iPhone17Pro 耗时保证。

### A7ALABS/apple-spatial-capture：优先参考的采集到导出流程

[仓库](https://github.com/A7ALABS/apple-spatial-capture)为 MIT 许可 Flutter 插件，包含原生 Swift 采集/处理实现。其高斯工作流已经覆盖：

1. ARKit 自动关键帧采集、相机位姿与点数据。
2. 曝光/白平衡锁定、模糊与跟踪质量反馈等采集措施。
3. 写出 Nerfstudio 或 COLMAP text 数据格式。
4. 调用其自带的 msplat Metal 引擎在设备端训练。
5. 标准 PLY 导出和训练预览。

但作者仍明确标注 iOS 训练 experimental，建议适中照片量、1000–3000次训练、通过降分辨率和限制增长管理手机内存。整屋上限、温度、跟踪漂移和成片清晰度不能据此视为已解决。

对 MemoryRoom 的合理复用是读取其原生采集、训练包装和导出代码，保留现有 Swift App 与场景协议；无需为了插件外壳将项目整体改成 Flutter。插件已有内核与 frs0n 分支是候选实现关系，选择/替换一个训练内核并对齐接口，不把两套内核顺次堆叠。

### rayanht/msplat：上游 Mac/Metal 内核

[仓库](https://github.com/rayanht/msplat)为 Apache-2.0，提供 Metal 训练、Swift/C++/Python接口和PLY输出。可以用作上游实现参照与 Mac 本地训练候选。

上游 README 的约70秒数字是在 M4 Max 上的特定训练数据与配置；不能外推成 M1 Pro 或 iPhone 整屋70秒。手机优先关注专门处理 iOS 内存约束的分支。

## 4. 其余方案如何选

| 项目 | 当前角色 | 对我们的适配判断 |
|---|---|---|
| [OOOSplat](https://github.com/ooolabdev/ooosplat) | 源码公开的照片/视频/全景到高斯桌面流程 | 已有同源学校执行经验，继续保留；不是 iPhone 直接训练 App。Mac 配准仍可能成为瓶颈。第一方Apache-2.0，依赖另计。 |
| [Brush](https://github.com/ArthurBrussee/brush) | Apache-2.0 跨平台高斯训练引擎 | 输出可接现有查看器；需要准备相机数据。文档列出 Android/浏览器，不等于已有成熟 iOS 整屋扫描 App。 |
| [LichtFeld Studio](https://github.com/MrNeRF/LichtFeld-Studio) | GPLv3+ NVIDIA桌面训练、编辑、导出 | 源码可免费构建；现成 Windows预编译下载是付费入口。Windows/Linux、NVIDIA/CUDA要求，不适合M1 Pro/iPhone直接运行。学校端可作为以后单独候选，不自动更换当前链路。 |
| Metashape + [Kotohibi教程](https://github.com/Kotohibi/3DGS_pipeline_guide) | 球面配准及转换工作流 | Metashape为商业环节，不满足本轮默认免费开源要求；保留教程思路。 |
| [ODGS](https://github.com/esw0116/ODGS) | 全景投影训练与CUDA光栅器 | 代码公开，逐场景优化；仍需准备相机和素材。源码有标准高斯PLY保存逻辑，格式可作为接入候选，未做本项目渲染验收。整套依赖许可另核。 |
| [360-gaussian-splatting](https://github.com/inuex35/360-gaussian-splatting) | OpenSfM + 球面高斯训练 | 整合参考，配置环节多；不如现有桌面应用省事，包含原3DGS等依赖，不能只凭公开仓库当成无限制商用SDK。 |
| [Splatter-360](https://github.com/thucz/splatter360) | 少全景视角前馈研究 | 有代码和预训练模型，公开流程围绕HM3D/Replica等数据；真实房间、输出资产与自有采集还需适配。优先级低于产品链路。 |
| [DAP](https://github.com/Insta360-Research-Team/DAP) | 全景深度估计 | 只生成几何先验，不是完整3DGS，不可单独代替扫描/配准/训练/导出。 |
| [SphereForge](https://github.com/tedngai/SphereForge) | 全景多阶段组合工程 | 表面流程完整，但需要多引擎/深度模块；仓库明确列出不同许可及非商业组件，不优先选作商用主线。没有本项目稳定性、耗时、画质证据。 |
| [PocketGS](https://arxiv.org/html/2601.17354v3) | 手机训练方法论文 | 有真实手机实验，值得学习位姿优化/几何初始化/内存设计；本轮未核实可直接集成的完整官方开源App/SDK，不作为现成工程承诺。 |

上述“源码免费”只说明无需订阅才能取得/自行构建相关代码，不代表所有模型权重、训练数据、依赖、设备、计算和软件分发成本为零。输出资产是否兼容与能否复制引擎进闭源App也是两个判断，GPL代码等应按实际集成方式审查。

## 5. 我们怎样复用，避免重新搭一条慢链路

1. 保留现有采集 App 和原始数据。参考成熟源码改进关键帧、曝光、模糊、位姿质量与补扫反馈。
2. 统一产出图像、逐帧内参、正确坐标约定的相机位姿、深度初始化点及采集身份。
3. 接入手机训练provider，输入为内核支持的数据格式。写COLMAP格式不等于必须重新执行COLMAP配准程序；ARKit测量也能转换成该格式，但跟踪误差不会因格式转换消失。需要明确区分测量位姿、优化位姿及重建覆盖。
4. 控制训练图像分辨率、高斯数量、迭代次数、内存、温度和取消/恢复。先支持有明确范围的场景，手机承载不了时允许用户明确选择Mac/学校处理，不能静默切换。
5. 统一输出标准PLY/SPZ与sidecar：capture_id、units/scaleStatus、坐标变换、训练provider/版本、质量警告。相机与采集资料保留用于后续对齐。
6. 现有Spark查看器导入模型，继续复用物品ID、记忆附件、快照和交互。源码已允许PLY/SPZ并通过SplatMesh读取；没有用这些候选的真实导出重新验证格式版本。

不要复制论文中的“训练秒数”作为拍摄到打开的总时间。特别是已有学校案例：配准1小时25分16秒，训练仅6分27秒。替换训练内核可能只缩短后者；想明显改善体验还必须处理采集位姿与配准。

## 6. 不随模型自动出现的能力

- 整体房间高斯不会自动变成独立椅子、水杯、柜门；依然需要独立采集/分割和场景组装。
- 拿走物品后需有真实空位数据或后续修复，否则留有原物品重影/空洞。
- 抽屉/柜门需要支点、轴向、行程、代理几何；视觉高斯不是碰撞体。
- SPZ缩小下载/磁盘体积，不保证运行时显存/排序开销按同样比例降低。低配手机网页还需要高斯数量分档、轻量资产或LOD；当前查看器导入路径明确为lod:false。
- 现有项目包容量256MB，需按整包资产控制，而非每件独立都占满256MB。

## 7. 本轮建议的取舍

**近期：**已有OOOSplat真实结果继续用于MemoryRoom，优先完善空间浏览与交互，不再要求用户购买闭源扫描App。

**下一条值得投入的免费手机路线：**现有Swift采集器参考apple-spatial-capture原生流程，选择经过源码/接口审查的msplat-ios训练内核。优先消除“手机拍完还要人工操作服务器”的体验成本。

**暂不当主线：**Metashape商业组合、SphereForge复杂多许可链路、Splatter-360/PocketGS研究复现。不能依据宣传演示认定其整屋效果优于现有方法。

完整采集体验和可靠成片还需要工程工作。目前没有核实到一个能无条件承诺“免费开源、iPhone随手扫完整屋、几分钟、任意视点高清、自动拆物品”的现成项目。现有开源组件足以搭建有边界的版本，但成熟度与上限应分开表达。
