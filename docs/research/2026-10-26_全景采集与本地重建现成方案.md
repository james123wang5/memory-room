# 全景采集与本地重建：现成方案选型

调研日期：2026-10-26。按用户要求使用 AnySearch MCP 检索，以 Lightpanda 读取官方正文。只做资料调研，没有安装软件、上传房间、运行测试、训练或重建。下列推荐是资料与项目需求的适配判断，不是同一房间的实测排名。

## 结论

可以复用现成产品，没必要把自研 iPhone 扫描器作为唯一入口。现阶段最值得保留两条输入路线：

1. **手机省事路线：Scaniverse 的经典手机本地扫描 → 导出 SPZ/PLY → MemoryRoom。**它不是开源训练引擎，但可以直接承担采集和处理，减少我们维护采集器的工作。
2. **全景相机、本地电脑路线：走动拍摄完整全景视频 → 厂商工具导出标准全景素材 → OOOSplat 全景流程 → 模型导入 MemoryRoom。**现成程度和 Mac 适配最贴近当前项目；不能因此宣称画质必定优于现有成片。

希望提高可控性时，再考虑“Metashape 球面配准 → Kotohibi 转换工具 → LichtFeld Studio”组合。它有完整图文教程，但不是全开源免费链路，操作与部署也更多。ODGS、Splatter-360、DAP 属于算法或研究组件，不应先当成成熟房间扫描 App 替代品。

## 1. 影石时光舱实际做了什么

[影石官方操作说明](https://onlinemanual.insta360.com/app/zh-cn/operation_tutorial/edit_function/3dgs)确认：

- 支持 X6、X5、X4 Air；输入是全景普通视频，生成用片段最长两分钟，不支持用照片直接生成。
- 推荐 8K/30fps、明亮静态环境，折返/S 形走动，关键对象另外绕拍。
- 本地素材要先处理，再上传云端重建；官方给出的生成时间约 90 分钟。
- 生成结果支持水平移动和上下左右看，属于可探索的三维空间。
- 当前不支持模型源文件下载、离线导出或生成后编辑。

因此，它适合参考拍摄与交互流程，当前不适合作为 MemoryRoom 的可编辑资产输出后端。短视频里的操作很快，不能据此推断后台训练也只用了几分钟。

[影石 Project Eternal 官方介绍](https://www.insta360.com/blog/enterprise/tech-behind-project-eternal-3dgs.html)还列出了 Splatica、Aholo、MipMap 等合作处理平台，其中包括云端服务和本地部署方向。这说明“全景相机采集 + 可替换重建软件”本身就是现有生态；但合作介绍不是这些平台质量、速度或开放接口的独立验证。本轮未购买或试用。

## 2. 候选方案对照

| 方案 | 素材及处理位置 | 可复用内容 | 当前选择理由与边界 |
|---|---|---|---|
| Scaniverse 经典手机模式 | 手机拍摄；手机本地处理 | 成熟采集体验、直接输出高斯模型 | 不买全景相机时最省事；非开源，不代表整屋近看必定清楚 |
| OOOSplat 全景流程 | 完整全景视频/多张全景；本地电脑 | 相机配准、训练、预览、编辑和导出 | 当前 Mac 主线候选；仍受素材、配准、训练分辨率和内存限制 |
| Metashape + Kotohibi 转换 + LichtFeld Studio | 全景视频抽帧；本地电脑/NVIDIA | 球面配准、遮罩、COLMAP 数据、训练与编辑 | 可控性较强，但组件多；包含商业软件，不能称全部免费开源 |
| inuex35/360-gaussian-splatting | 全景照片；OpenSfM + 高斯训练 | 原生球面相机流程与代码 | 研究工程路线；依赖配置和使用体验不如完整桌面应用 |
| ODGS | 全景图像与相机数据；CUDA | 适配球面投影的高斯光栅化与训练 | 值得作为后续引擎候选；不是采集、配准、编辑一体化 App |
| Splatter-360 | 多个全景视角；预训练模型推理 | 少视角快速形成高斯的研究方向 | 有代码和权重；公开流程主要围绕 HM3D/Replica，真实手机房间需适配 |
| 影石 DAP | 全景图；深度模型推理 | 全景深度先验 | 不是完整 3DGS 重建，也不是时光舱开源版 |
| SphereForge | 全景视频；CUDA 多阶段流程 | 抽帧、遮罩、深度、训练、补洞的组合设计 | README 很贴近需求，但本轮没有其稳定性、质量或速度证据，不选为第一主线 |
| Scaniverse Web 360 | 全景视频上传云端 | 现成全景重建并导出资产 | 可以作为商业参照；不满足完全本地，不与经典手机本地模式混淆 |

## 3. 为什么仍然把 OOOSplat 留在候选里

用户当前不满意的结果来自普通手机视角输入；这不能独立证明 OOOSplat 的全景输入也会得到同样结果。变化首先发生在采集覆盖与相机配准，不是换一个名称就换了全部算法。

当前公开 main 分支说明具备全景处理：完整 2:1 等距柱状视频/图片 → 球面相机配准 → 已注册视角转六个透视训练面 → Brush → 标准高斯输出。Mac 上配准使用 CPU，训练使用 Metal。**公开 main 不等于用户当前安装包**，应用版本与实际任务配置尚未核对。

注意输入必须是真正的完整 360°×180°全景。不能直接给它双鱼眼画面、裁切全景或厂商私有原片；影石素材需先由厂商软件导出兼容格式。

最值得留意的是训练分辨率。官方全景文档列出快速/均衡/精细的 ERP 宽度上限为 2048/3072/4096，对应单面上限 512/768/1024。**用 8K 拍摄，不等于桌面工具在用完整 8K 训练。**这不是当前用户模型模糊的已确认原因，但说明高分辨率采集后还必须看实际训练配置，不能只看输入视频规格。

来源：[全景视频流程](https://github.com/ooolabdev/ooosplat/blob/main/docs/PANORAMA_VIDEO_V1.md)、[全景图片与训练配置](https://github.com/ooolabdev/ooosplat/blob/main/docs/PANORAMA_IMAGES_V1.md)。这些文档还保留历史实现和旧测量，不能把旧配方耗时当作现行全部档位表现。

## 4. 全景能减少哪些麻烦，不能解决哪些问题

**能减少：**需要反复朝不同方向举手机的次数、转身时失去共同画面的概率、因只盯着局部物体而漏掉周围结构的问题。

**仍然需要：**相机在空间里平移，邻近区域有共同内容；保持场景静止；补拍近景和被家具挡住的表面。站在同一位置转一圈，得到的是一个观察点周围的颜色，不能自动获得所有背面与内部。

全景 8K 是分布在整个 360°方向上的像素，并不等同于每个方向都是一张 8K 近照。近距离拼接缝、拍摄者、白墙、镜面、运动模糊和阴影仍可能影响结果。增加普通近景照片有潜力补细节，但重建链路必须明确支持混合投影：**OOOSplat 当前说明不能把普通与全景素材混合补拍，不能直接照搬混合路线。**Kotohibi 另有混合相机工作流，应按具体工具的能力选取。

[Niantic 官方全景采集指导](https://www.nianticspatial.com/docs/scaniverse/360camera/)仍要求相邻区域重叠、缓慢平移、闭环、适度高低变化，并提醒避开双镜头拼接线附近的近物。这些建议说明成熟产品也不是完全不受采集质量约束。

## 5. 手机的“全景”是否可以代替全景相机

要区分三个输入：

1. **系统相机横向扫出来的宽幅拼接照片。**不能默认它是完整球面全景，也不能直接套用 2:1 ERP 相机模型。
2. **在一个位置拍成完整 Photo Sphere。**适合该位置的环视或提供单目深度输入；真实平移探索仍缺少多位置观察。
3. **从多个位置拍完整全景，或用手机普通相机走动采集很多视角。**可以用于重建，但要有正确投影、共同特征和位姿处理。

若目的是立即减少现场操作，现成 Scaniverse 手机扫描比我们重新做一个“手机拼全景 + 训练器”更直接。它的官方当前说明保留了不限次数的设备端高斯采集/处理及 SPZ 等导出。这里推荐的是成熟产品的输入能力，不是建议把闭源核心代码搬进项目。

## 6. 速度该怎样判断

| 环节 | 当前能够据实说的内容 |
|---|---|
| 影石时光舱采集 | 官方建议两分钟内；需要合适范围、光照和走动路径 |
| 影石时光舱生成 | 官方约 90 分钟云端生成；不是两分钟拍完后立即成片 |
| Scaniverse 手机本地 | 官方确认设备端处理；本轮没有用户这间房的可靠分钟数 |
| M1 Pro 本地全景处理 | 缺少同素材同设置耗时；CPU 配准可能占明显时间，不能承诺整屋数分钟 |
| 学校 A40 | 可选 CUDA 研究/训练路线；仍有配准、数据准备、队列和环境成本，当前没有全景数据实测 |
| ODGS/前馈方法的论文速度 | 方法速度或渲染帧率不能直接当作从原始视频到可编辑房间的总时间 |

此前整屋 3–8 小时只是旧链路的粗规划，不能固化为所有全景方案的必需时间。反过来，也没有证据支持在 M1 Pro 16 GB 上“任意整屋、几分钟、高清无伪影”的承诺。

补充：当前本地 STATUS.md 已记载另一聊天完成的真实学校任务：493 张普通手机照片，COLMAP 1 小时 25 分 16 秒，OOOBrush 6 分 27 秒。这里仅引用既有记录，没有重新运行或独立复核日志；它提示当前瓶颈可能主要在相机配准，而不是训练本身。该记录不是全景路线耗时，也不能推导 A40 全景一定更快。

## 7. 推荐采用的产品流程

### 近期：复用已有采集产品

MemoryRoom 接收外部 SPZ/PLY/GLB，不让用户必须先用我们的采集 App。手机已有数据继续保留；对想快速得到房间的用户，提供 Scaniverse 导出入口说明。自研采集器保留为需要原始深度/位姿时的可选入口。

### 全景本地主线

全景相机拍摄 → 厂商拼接/规范化导出 → OOOSplat 全景处理 → 原模型保留 → 可选现成编辑器清理漂浮高斯 → MemoryRoom。

优先复用软件，自己的工作集中在素材交接、模型接收、起始相机、站立式探索、物品/记忆管理。全景链路接收的应包括相机配准资料，不应只留下 PLY：单独的高斯点坐标通常不足以可靠恢复原始站位、地面朝向和真实尺度。

### 后续可控质量路线

需要更好地控制球面配准、遮罩和训练时，参考 [Kotohibi 的完整图文教程](https://github.com/Kotohibi/3DGS_pipeline_guide/blob/main/%5BEN%5DEasy%26Fast%203D%20Gaussian%20Splatting%20workflow%20with%20360%20Camera.md)，采用现有转换工具与训练器。Metashape 是商业组件；LichtFeld Studio 的 CUDA 环境也不能直接视为已经适配学校服务器。

如果未来重点变成少数照片快速预览，可以研究 Splatter-360。如果重点是全景深度初始化，可以研究 DAP。两者先作为可替换模块，不把整个产品押在尚未接入的研究模型上。

## 8. 对画质、编辑与本轮工作的界定

没有从公开资料得到“某个开源项目在用户这间房一定达到影石精度”的证据，也没有同数据横向比较。展示视频可能选取了最佳区域与观看路径，不能由漂亮演示推导出任意位置均无伪影。

全景重建解决房间外观输入；独立椅子、柜门开合、移走后的背景仍需要资产拆分和缺失内容处理。不能把可漫游与物体可编辑混为一谈。

用户最新要求为先调研，故本轮暂停应用开发。前面扫描换区等源码修改保留在工作区，但未完成整批交付、未构建或安装；相机观看方式修改仍未实施。本报告不代表这些功能已经可用。
