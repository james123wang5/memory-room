# 世界模型替代扫描、快速重建与独立交互资产

日期：2026-10-26。用户实测Scaniverse：速度和便利性可接受，但细节、缺失、自由视点质量与导入方向不达目标；允许房间、物品、柜门和柜内物件分别采集。约束是尽量免费、低设备门槛、速度快、足够清晰、可导出且能做独立交互。

本轮使用已配置AnySearch MCP完成15项搜索，并提交反馈；公开正文优先Lightpanda。Marble价格页的静态抓取为空，回退kimi-webbridge读取公开动态价格页；SHARP/Spark文档部分静态提取失败时用内置网页读取。不注册账号、不上传用户房间、不调用生成API、不付费、不安装或执行模型，不运行测试。

## 1. 结论与推荐顺序

没有核实到一个现成方案同时保证：任意整屋近看高清、少量随手采集、普通手机快速生成、完全免费、自动拆物品与关节、还能输出通用资产。

目前值得集中探索的只有两条新对照，不继续无目标地增加小仓库：

1. **WorldMirror2.0真实重建**：现有照片/视频、相机内参与深度先验 → 前馈几何/相机/标准高斯PLY → 必要时同源Brush精修 → MemoryRoom。目标是减少传统配准成本，保持实拍依据；没有证明画质一定优于Scaniverse。
2. **FlashWorld生成式对照**：单张照片/文本 → 生成SPZ/PLY → MemoryRoom。目标是验证更少输入、更完整外观是否满足产品；新增细节可能不是原房间事实，不能无标记地当作真实记忆重建。

Marble适合免费网页体验，但当前免费档不能完成“导出文件→本地网页”闭环。HY-World2.0完整生成链配置很重，不是普通电脑低成本生成的直接答案。SHARP可以做局部视角研究，权重许可不适合作为默认商用内核。

## 2. 真实截图能说明什么

本次手机截图在Scaniverse内，桌面物件、椅子轮廓明显好于之前GLB，但柜面、桌沿和地面仍模糊。仅凭单张截图不能确认完整覆盖、真实几何误差、训练参数或是哪一个环节造成全部质量损失。用户报告的效果不达标是有效产品反馈，不把官方宣传等同验收。

用户之前想同时满足的能力需分开：高保真外观、可信几何、空间可探索、独立对象、关节与内容。一个房间高斯输出不自动具备物体身份、关节或碰撞；生成式世界的外观完整也不意味着真实尺寸和文字都正确。

### WorldMirror2.0为什么值得作为下一项重建对照

官方接口接收相机和深度先验，因此现有MemoryRoom采集包中的RGB、ARKit内参/位姿、LiDAR深度有复用价值。文档规定先验位姿为OpenCV c2w，需从现有OpenGL表示做明确转换；不能直接把矩阵换文件名。模型还会将外参相对首视角归一化，不能把输出默认当原ARKit世界坐标和已校准米制。

标准输出含`gaussians.ply`、`points.ply`、相机文件与深度。前者才是高斯；点云不能当成训练成片。默认推理长边目标952像素，支持调整；输出图保存最大1920不等于推理曾看过1920原始细节。不能在未经真实结果比较前承诺文字或细腿比Scaniverse更清晰。

提议的“可选Brush精修”属于待适配方案：要把正确相机/初始化高斯/点云和图像交给训练器，并保留一致坐标。尚未写适配器、验证续训兼容、安装模型或运行推理。不将这一提议称为已经可用的现有流水线。

### FlashWorld为什么可以尝试，但不能称低配秒出

仓库明确支持CLI导出SPZ/PLY。学校A40显存48GB在容量上有理由考虑24/30GB配置，但CPU内存配额30GB、offload与依赖仍要核实。A800的20秒只是作者特定硬件数字，没有本项目A40计时。

仓库给出[公开在线Demo](https://huggingface.co/spaces/imlixinyang/FlashWorld-Demo-Spark)，本次检查其Space README为静态Spark前端，许可证标为CC-BY-NC-SA4.0；没有实际提交生成，没有确认当前后端运行、免费上传额度或下载可用性。主仓库标Apache-2.0，不能据此忽略其demo及依赖/权重条款。

## 4. Marble免费体验和按次费用

2026-10-26读取实际价格页：

- Free：7000额度、最多4个world，主要用于网页生成体验。
- Standard：20美元/月，列出高斯文件、全景、低分辨率碰撞网格导出。
- Pro：35美元/月，另外列出高质量贴图网格和商业权利。
- 网页额度和API额度分开。不能把网页登录赠送额度当作开发API余额或自动导出授权。

API按生成/处理事件的credits计费，不是普通聊天的输入/输出Token，也不要求开发者必须购买网页月订阅。当前1美元=1250credits，最低购入5美元；现行示例：

| API请求 | credits | 换算美元 |
|---|---:|---:|
| 普通单图→draft | 230 | 0.184 |
| 多图/视频→draft | 250 | 0.20 |
| 普通单图→Marble1.1 | 1580 | 1.264 |
| 多图/视频→Marble1.1 | 1600 | 1.28 |
| HQ mesh导出事件 | 3500 | 2.80 |

Plus还可能增加可变生成费；修改/重试/额外动作需另算。基础collider mesh与收费HQ mesh不要混淆。素材上传/状态轮询等并非每一HTTP请求都收费；实际账单依官方usage事件。此处仅解释当前文档，不在本轮付费或启用自动充值。

生成一次并下载资产后，在自有网页本地浏览不会持续调用世界生成API。记忆对话LLM的Token成本是另一个模块，不应与资产生成费用混算。服务器若免费向所有开源软件用户提供生成，算力费用仍由提供者承担；开放源码不会使云算力自动免费。

来源：[API定价](https://docs.worldlabs.ai/api/pricing)、[PLY/GLB导出FAQ](https://docs.worldlabs.ai/api/faq)、[网页计划](https://marble.worldlabs.ai/pricing)。

## 5. 方向乱套是独立的接收端缺口

已读`apps/viewer/src/main.ts`与`viewport.ts`：新导入资产只有单位选择，节点旋转初始化为[0,0,0]；渲染器支持资产rotation，但当前导入没有Scaniverse来源预设、地面标定向导或通用up-axis校准。不能据此证明每个源文件都坏了，也不能对所有SPZ/PLY统一硬转180度。

建议作为独立产品修复：

1. 保留原文件与source元数据，统一映射到右手Y-up。
2. 允许一次设定地面/朝向/尺度，保存整体变换。
3. 让用户确定室内起始相机，避免自动包围盒视角落到房间外。
4. 后续独立物品通过同一场景坐标或显式对齐变换加入，关节与碰撞体随同转换。

这是待实现方案，本轮没有更改用户项目或源码。可先利用现有摆放设置手动转正，但不应让每个客户反复猜Euler角。[Spark变换能力](https://sparkjs.dev/docs/splat-mesh/)

## 6. 物品、柜门与真实文字的可交付结构

房间可继续高斯；独立物品可以高斯，也可以高质量带贴图网格。后者更易做碰撞、拿取与柜门运动，不需要要求所有资源必须同一种表示。

1. 背景保持一个稳定状态；准备移走物件后的真实空位，避免拿起后原物体仍留在背景。
2. 重要小物体单独近距离拍摄。默认物体固定、手机绕拍；持续手拿转动会破坏当前静态场景/ARKit位姿假设。
3. Apple Object Capture有官方引导、分段绕拍、适合物体的翻面流程以及手机本地重建，可作为高质量网格物件入口。输出是网格；不是给我们免费提供手持任意运动追踪和完整整屋高斯。[Apple官方讲解](https://developer.apple.com/videos/play/wwdc2023/10191/)
4. 柜体、门板、抽屉、内部资产分开，录制时保持各段静止；设置轴、支点、开合范围和代理几何。世界模型生成一个柜子不会自动产出正确可动关节。
5. 用户允许分别扫描时，一期可人工对齐/标支点，不必等全自动关节推断。但这些部件要共享或校准坐标，不能假定不同扫描文件自然重合。
6. 书页、标签和屏幕内容用原始高清照片/附件保真；生成模型不能保证文字内容真实，视觉清晰也可能是补出来的。

## 7. 另一种真正降低门槛的产品取舍

如果“高清回忆”比“任意位置自由走动”更重要，可用多站位高清全景/照片作主视觉，热点切换站位，在其上提供独立3D物品的拿取观察与记忆面板。多数画面保留原始像素，省去整屋3D训练，对普通手机更友好；代价是走动位置受限，并非任意6DoF三维漫游。柜门可通过独立3D柜子或开/关视图状态交互，不能与自由视点几何开门混称同一效果。

如果任意漫游与真实几何都必须保留，则继续真实重建，以局部近景资产补强，不把全屋一个模型承担全部分辨率。生成式世界作为明确标注的可选分支，不替代真实性要求。

## 8. 建议的下一步及验收依据

只提议，不在本轮执行：

1. 先补接收侧坐标/起始视点校准，降低现有可用模型的导入阻力。
2. 复用已有真实采集，适配WorldMirror2的相机/深度先验；保留Scaniverse与现有Brush结果作对照。不要求重新完整扫描、不覆盖原始素材。
3. 用一张已有照片作FlashWorld生成式对照，核对导出的SPZ/PLY能否加载和是否保留关键真实物件。需要云端的版本另经用户明确授权上传，不能自动把房间发到公开demo。
4. 再加入一件独立物品和一块柜门，完成观察/归位/手动关节，评价前置资产是否足以支撑后续开发。

比较维度为采集人力时间、端到端耗时（含准备/排队/下载）、峰值显存/主存、同位置近景细节、新视点漂浮与缺失、关键物品和文字真实性、网页性能、对齐操作次数以及实际生成费用。不能仅凭网络PSNR/几何榜单或演示视频断定用户房间达到要求。

许可方面，HY-World2使用Tencent定制许可，文件列出地域等限制；SHARP模型限研究，明确不包含商业产品开发。FlashWorld仓库、demo前端、模型依赖也需分开核对。以上仅标记直接看到的工程选型限制，不是全依赖许可审计或商用授权结论。
