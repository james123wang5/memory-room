# 学校 A40 重建时间与接入估算

调研日期：2026-10-25 至 26。未连接学校机器，没有执行训练或跑基准；没有学校 CPU、内存、调度队列与 VPN 实测速率。以下是带条件的工程时间预算，不是已测得的性能。

## 结论

如果能独占 A40，并把照片配准和训练都放到服务器，通常值得期待比 M1 Pro 16GB 更短的计算时间和更宽裕的显存；但不能保证整屋都压到固定几十分钟。此前 Mac 的 3–8 小时本身也是规划估计，不能据此计算可靠加速倍数。

按单张完整 A40、约 8–16 个可用 CPU 核、32–64GB 主存、服务器本地 SSD、约 300–1200 张有效照片、约 1–2K 级图像长边、常规 3DGS 预算来规划：

| 输入规模 | 配准＋训练＋导出的规划时间 | 说明 |
| --- | --- | --- |
| 300–600 张、视角连续、纹理较好的房间 | **约 45–150 分钟** | 较理想的首次预算；不是针对现有那 335 张素材的测量 |
| 600–1200 张、遮挡和弱纹理较多的整屋 | **约 1.5–4 小时或更久** | 照片匹配、增量配准与更大模型可能占主要时间 |
| GPU 共享、CPU 分配少、机械/网络盘、反复配准失败 | 无法给出窄区间 | A40 仍可能等待其他环节，并不能排除超过上述范围 |

在第一档条件下，可把相机配准先按约 15–75 分钟、高斯训练按约 20–60 分钟、整理导出按约 5–15 分钟分配预算，取整给出全程区间。这里是推算，不能将分项上限当保证；训练参数、注册相机数和高斯数会改变耗时。

## 推算依据与不能直接套用的数字

- NVIDIA 官方列出 A40 为 Ampere、48GB 显存、696GB/s 显存带宽。显存容量有利于较大模型，但不等于全部 48GB 都会分给学校用户，也不意味着速度与显存容量成比例。[A40 官方规格](https://www.nvidia.com/en-us/data-center/a40/)
- gsplat 官方的 Mip-NeRF 360 七场景数据中，30k 步单 GPU 平均约 35 分 49 秒，Room 单场景约 1708 秒；该组数据使用 TITAN RTX，不是 A40，也不包括手机采集、网络传输和完整照片配准。页面另有 A100 的特性对比，不能混成同一硬件的数据。这里只支持“常规 CUDA 高斯训练常见为几十分钟量级”的判断，不是学校 A40 的承诺。[gsplat 官方评测说明](https://docs.gsplat.studio/main/tests/eval.html)
- COLMAP 的特征提取/匹配可用 GPU，但位姿求解的耗时还受 CPU、照片数量和匹配图影响。当前官方文档也有 GPU bundle adjustment 等能力，具体是否可用依学校安装版本和编译设置。不能笼统说所有配准都只跑 CPU，也不能认为有 NVIDIA 卡就全部自动加速。[COLMAP FAQ](https://colmap.github.io/faq.html)

没有找到与“我们的手机素材＋学校这张 A40＋指定训练器配置”完全匹配的公开基准，因此没有用浮点算力比例硬算训练时间。这里也没有宣称 gsplat、OOOBrush 和旧 Brush 的耗时可直接互换。

## VPN、传输与排队

总墙钟时间 = 上传 + 学校排队 + 服务器计算 + 结果下载。VPN 提供网络通路，不参与重建计算。

5GB（十进制）素材的理论纯上传时间：

| 持续实际传输速率 | 时间 |
| --- | --- |
| 20 Mbps | 约 33 分钟 |
| 50 Mbps | 约 13 分钟 |
| 100 Mbps | 约 7 分钟 |

加密、拥塞、丢包、很多小文件与服务器存储都会增加实际时间。输入最好按采集或整理批次打包传输，结果通常只下载模型、相机与任务记录，原始素材本地仍保留。

学校队列可能立即开始，也可能等待数小时，当前没有学校资料，无法估计。拿到 GPU 作业资源后再启动处理，不能默认 SSH 登入的登录节点就是 A40 计算节点。

## 未来接入路径

手机采集 → Mac 整理照片与交接记录 → VPN / SSH 传输 → 学校调度器分配 A40 → Linux 命令行 COLMAP ＋ CUDA 高斯训练器 → 导出标准 PLY、相机和日志 → 回传 MemoryRoom → 同一套物品与记忆系统。

不要求在服务器上打开 Mac OOOSplat GUI。Mac 和学校执行器可以不同，输出仍要遵守同一资产协议：来源、采集身份、模型格式、未知尺度/坐标提醒与任务状态。服务器可采用支持无界面运行的工具，具体版本和安装命令需结合学校环境确定。

如果学校使用 Slurm，用作业脚本提交；其他调度系统使用对应机制。SSH 会话仅负责提交与查看，长任务不依赖一个前台终端一直保持连接；日志与结果在作业目录保留。未经用户给出连接资料和明确启动请求，本轮没有连接、传输或占用学校 GPU。

实际接入需要：SSH 主机别名/跳板方式、调度器及队列名称、允许的 GPU/CPU/内存资源、项目存储位置、CUDA/驱动与 COLMAP/训练器版本。无需把密码或私钥写进 MemoryRoom 项目。当前实现只保存本地接入计划，未声称已能一键远程训练。
