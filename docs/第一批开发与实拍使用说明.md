# MemoryRoom 第一批开发与实拍使用说明

日期：2026-10-25。源码版本：iPhone 0.4.0 / 场景格式 v2。

本批最初完成的是代码实现。2026-10-25 随后按用户请求，已完成安装所需的 Release 编译和签名，并在 iPhone 17 Pro 上覆盖更新为 0.4.0（build 4）；设备应用列表已确认版本。未卸载旧应用，未运行测试、模拟器、浏览器验证、样例训练或实拍；没有上传房间或调用付费服务。当前请用户自行打开 App 运行，安装成功不等于扫描画质已经验收。

## 1. 本批做到了哪里

- 继续使用现有 SwiftUI + ARKit + RoomPlan、Mac Brush v0.3.0、Three.js + Spark。
- 采集默认只扫空间；可选择局部区域或整间房。
- 局部区域使用左右侧移、换高度的指导，不要求三面墙、地面或全屋闭环。
- 保留运动、光照、深度、重叠与追踪提示。记录条件与完成建议分开：完成建议不再成为永久拦截。
- 达到基本有效视角数量后，用户可以继续补拍，也可以先结束并生成预览。
- 旧版采集没有指导记录时仍可进入生成；真实来源、文件、相机参数及必要深度仍要可读取。
- 标准生成与快速预览都直接生成模型，不做留出视角渲染、画质评分或自动成片验收。
- 可停止、重新生成、查看历史任务和下载处理记录。重试创建新任务，不覆盖旧模型。
- 原始采集、转换结果、模型和处理记录保留在 Lexar。
- 场景 v2 区分布局、关节状态、文字内容和资产；读取 v1 时保留旧物品编号与变换。
- 网页增加 GLB 网格导入，支持内嵌贴图。没有接入 Draco、Meshopt、KTX2 解码或外部贴图引用。
- 导入物品不再强制改成 45 厘米，可选择米、厘米、毫米；导入后保留来源坐标。
- 项目包上限调整到 256 MB，保存端与导入端一致。仍是内存打包加载，分块/流式与手机端空间库属于第三批。

## 2. 先更新手机 App

**2026-10-25 新版已安装。现在直接在手机打开“MemoryRoom采集”，按第 3 节操作即可。** 以下步骤保留供后续重新安装使用。

1. 用数据线连接并解锁 iPhone。
2. 双击项目根目录的 `打开手机采集工程.command`，在 Xcode 打开工程。
3. 选择 MemoryRoomCapture，运行目标选择你的真实 iPhone。在 Signing & Capabilities 选择自己的 Apple Team，使用原来的应用标识 `local.memoryroom.capture`。
4. 点击 Run，执行安装所需的编译并更新 App。这里只是你安装应用的操作，不需要运行 Tests。
5. 不要先卸载旧 App，以免丢失手机里尚未导出的采集。若出现签名或开发者信任提示，在设备和 Xcode 中处理。

后续重新安装时如果出现编译错误，将错误文字发回。本次已编译和安装成功，但尚未做运行或扫描功能验收。

## 3. 第一次建议这样拍

1. 选择“局部区域”，例如书桌与后方墙角，保留“只扫描空间”。关闭演练数据。
2. 擦净镜头，保持均匀光线，暂时不要移动物品、打开柜门或拉抽屉。
3. 进入采集，等跟踪稳定后点“开始扫描”。
4. 让目标始终处于画面里，身体沿弧线缓慢侧移；相邻画面保留共同的家具边角。
5. 稍微抬高或降低手机，再从另一方向拍回来。不要只站着旋转手机。
6. 优先处理当前提示：移动过快就减速，太暗就开灯，重叠不足就退回刚才能看到相同家具的位置。
7. 至少记录 30 个有效视角后可以结束局部扫描；数量是基础条件，不是成片质量保证。整间房基本结束数量为 60。
8. 点“完成空间扫描”。若仍有补拍建议，可以继续补拍，也可以选择先完成后查看结果。
9. 点“打包采集”，通过隔空投送或“存储到文件”把 `.capture.zip` 放回 Mac，建议保存在本项目 `data/raw/iphone-exports/`。

整间房模式使用沿可走路线慢走、换位置观察、回到起点的指导。颜色只针对已识别表面，不能表示墙后或家具背后已经被拍到。

## 4. 让电脑生成空间

1. 双击 `启动工作台.command`。如果工作台旧服务仍在运行，先关闭旧服务对应终端，再重新启动，以加载新版任务管理代码。
2. 打开工作台中的“导入手机采集”。
3. 选择 `.capture.zip`，首次可选“标准生成”；希望先看布局可选“快速预览”。
4. 点击“保存采集并生成空间”。保持电脑运行、硬盘连接。
5. 生成完成后点“打开空间预览”。如果当前有未保存编辑，界面会先提醒。
6. 由你查看效果；满意后点“保存到硬盘”。保存保留上一版本，也可以导出 `.room.zip` 备份。

标准生成：6000 步、最长边 1024、高斯上限 400000、最多约 300 个训练输入视角。
快速预览：2000 步、最长边 768、高斯上限 180000、最多约 180 个训练输入视角。
这些是实现中的起始配置，不是实测画质或耗时保证。过程不调用收费 API。

## 5. 中断与结果不满意

- 手机中断或退出：回首页打开“找回已有采集记录”，可重新导出已有素材；不直接将新 AR 会话接入旧坐标。
- 正在扫描时暂停：保留当前会话，可以继续补拍。
- “重扫本阶段”：旧帧保留为 discarded，新段单独记录，不混入当前训练。
- 电脑任务停止或失败：从历史记录打开任务，点重新生成。不用重复上传已完整保存的采集包。
- 改用快速预览：建立新任务，之前的结果保留。
- 模型缺洞或模糊：保留本次素材和结果，记录具体区域，后续据此修改采集或生成架构。

本批没有跨会话自动拼接、局部模型增量修补或自动保证补拍成功。后续可以复用保留的数据实现这些功能。

## 6. 回传给我什么

提供以下任意组合即可：

- 生成任务中的“下载本次处理记录”。
- 结果截图或你观察到的问题，例如某面墙模糊、桌腿漂浮、镜头初始方向不合适。
- 采集包或生成项目包在 Lexar 的位置。
- 手机上的具体提示，以及是否一直无法增加有效视角。

不需要你整理训练文件。原始照片、相机位置、深度、转换数据和日志已经按任务保留。

## 7. 文件位置

- iPhone 源码：`apps/capture-ios/MemoryRoomCapture/`
- 场景协议与打包：`packages/scene/src/`
- 工作台：`apps/viewer/`
- 本地任务与生成：`tools/capture_jobs.ts`、`tools/automatic_reconstruction.py`
- 导入原件：`data/raw/capture-imports/<编号>.capture.zip`
- 每次生成：`data/processed/jobs/<任务编号>/`
- 生成模型：任务目录 `model/export_6000.ply` 或 `model/export_2000.ply`
- 结果包：任务目录 `result.room.zip`
- 生成日志：任务目录 `model/train.log`
- 原始数据摘要：任务目录 `input-summary.json`
- 当前保存空间：`data/projects/current.room.zip`
- 上一版本：`data/projects/previous.room.zip`
- 本次改动前源码备份：`artifacts/source-backups/batch1-2026-10-25/`
